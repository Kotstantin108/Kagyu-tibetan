# Задание: веб-приложение для изучения классического тибетского через игры

Этот файл — единственный источник контекста для следующей сессии. Сначала прочитай
его целиком, затем `README.md`, `content/review-notes.md` и память проекта
(`~/.claude/projects/.../memory/content-pipeline.md`). Код читай по мере надобности.

## Что уже сделано (не переделывать)

Репозиторий: https://github.com/Kotstantin108/Kagyu-tibetan (ветка `main`, `gh` залогинен
как Kotstantin108). Сайт: https://kotstantin108.github.io/Kagyu-tibetan/ (GitHub Pages,
деплой через `.github/workflows/deploy.yml`: валидатор → unit-тесты → Playwright-смоук →
штамп версии в `site/config.js` → публикация `site/`).

- **Контент.** RYI *Classical Tibetan Grammar Handbook* уроки 1–7 (весь учебник) и
  Bialek *A Textbook in Classical Tibetan* упражнения уроков 1–11: 18 наборов, 1005 слов,
  939 предложений. Уроки 12–18 Bialek — сплошные чтения без упражнений, не включены.
  Авторство в `content/*.tsv` (формат описан в README), сборка
  `node scripts/build-content.mjs`, проверка `node scripts/validate.mjs`. Переводы:
  английский из учебников, ru/de/fr/pl машинные (мои), лежат в `content/lang-<xx>.tsv`
  по английскому ключу; интерфейс показывает пометку о машинном переводе при
  неанглийском языке. Список для вычитки — `CONTENT_REVIEW.md`.
- **Движок** `site/src/engine/` (чистые функции, 53 теста `npm test`): выбор предложения
  с одним новым словом, холодный старт, интервальное повторение (уровни 1/3/7/14/30/60/120
  дней, поля `level`/`due` у слова), трудные слова (`#/play/hard`), стрик, проверка по
  тексту плиток, слияние прогресса, Wylie (`wylie.js`).
- **Интерфейс** `site/src/screens/`: игра с тремя упражнениями (плитки, выбор смысла,
  ввод Wylie), словарь с примерами, справочник грамматики `#/grammar`, прогресс,
  настройки (язык, тема auto/light/dark, плитки, Wylie под плитками, экспорт/импорт,
  код переноса, Google-синхронизация, если задан Client ID). Онбординг при первом
  запуске. Клавиатура. Пять языков интерфейса `site/src/i18n/*.js` (тест на равенство
  ключей).
- **PWA**: `manifest.webmanifest`, `sw.js` (network-first, кэш по версии), иконки,
  шрифт Noto Serif Tibetan в `site/fonts/` (Noto Sans Tibetan снят с Google Fonts).
- **Сообщить об ошибке** сейчас — ссылка на предзаполненный issue GitHub
  (`site/src/report.js`, `REPO_URL` в `site/config.js`); требует аккаунта GitHub у
  пользователя. Это переделывается в задаче 2.

Технические ограничения остаются: чистый HTML/CSS/JS на ES-модулях без фреймворков и
сборщиков; сайт открывается из `site/` любым статическим сервером; mobile-first, тап-зоны
≥ 44px, без горизонтального скролла на 360px; прогресс только в localStorage; никакой
обязательной регистрации, аналитики, трекеров. Секреты в репозиторий не попадают.

Рабочие привычки: файлы с бэкслешами и кавычками писать инструментами Write/Edit, а не
heredoc-ами (bash их портит); после правок всегда `node scripts/validate.mjs && npm test
&& npm run smoke`; коммитить и пушить в `main` только проверенное.

## Новые задачи (делать по очереди, после каждой — коммит, пуш, короткий отчёт)

### Задача 1. Кнопка смены темы в шапке

Сейчас тема переключается только селектом в настройках (`settings.theme`:
`auto | light | dark`, применяется функцией `applyTheme()` в `site/src/app.js`,
CSS-токены в `site/styles.css` под `:root[data-theme="dark"]` и
`@media (prefers-color-scheme: dark)`).

Сделать:
- Кнопку в `site/index.html` внутри `.header-inner` рядом с селектом языка: иконка
  солнце/луна (inline SVG, без внешних библиотек), 44×44px, `aria-label` из i18n
  (`settings.themeToggle` на пяти языках), `aria-pressed` по текущему состоянию.
- Нажатие переключает между `light` и `dark` (из `auto` — в противоположную текущей
  эффективной теме) через `store.update(p => setSetting(p, 'theme', v))`; селект в
  настройках остаётся и показывает актуальное значение.
- Иконка обновляется из `applyTheme()` (там уже есть подписка на изменения store и на
  `prefers-color-scheme`).
- Проверить на 360px, что шапка не ломается (бренд, кнопка, селект в одну строку), и
  что `meta theme-color` меняется.

### Задача 2. «Сообщить об ошибке» с автоматическим заведением issue в GitHub

Цель: пользователь без аккаунта GitHub жмёт кнопку в игре или словаре, пишет пару слов,
и в репозитории появляется issue. Статический сайт не может хранить токен GitHub,
поэтому нужен крошечный эндпоинт на нашем сервере (см. задачу 4; задачу 2 делать после
задачи 4 или вместе с ней).

Сервер:
- Node-сервис `report-api` (один файл, без зависимостей, `node:http`) на
  `127.0.0.1:8091`, systemd-юнит, запускается от отдельного пользователя. Код хранить
  в репозитории в `server/report-api/` (сервис + unit-файл + README), на сервер
  копировать деплоем.
- `POST /api/report` с JSON `{ kind: 'sentence'|'word', id, tib, translation, lang,
  message, page }`. Валидация: `message` 10–2000 символов, `id` по регулярке
  `^[a-z0-9'\-.]+$`. Ответ `{ ok: true, url }` или 4xx.
- Создание issue через GitHub REST `POST /repos/Kotstantin108/Kagyu-tibetan/issues`
  с заголовком `Sentence s123: <tib>` / `Word <id>: <tib>`, телом из полей и меткой
  `content`. Токен — fine-grained PAT с правом Issues: write только на этот репозиторий;
  лежит в `/etc/report-api.env` (`GITHUB_TOKEN=...`, права 600), в репозиторий не
  попадает. Токен создаёт пользователь (Settings → Developer settings → Fine-grained
  tokens); попросить его об этом и дождаться.
- Защита от спама: лимит 5 запросов в час с одного IP (в памяти), honeypot-поле,
  максимум 1 issue на один `id` в сутки (перед созданием искать открытые issue с тем же
  заголовком через `GET /search/issues` и дописывать комментарий вместо нового issue).
- CORS: разрешить только origin `https://tibetan.itjoy.space`.
- nginx: `location /api/ { proxy_pass http://127.0.0.1:8091; }` в vhost
  tibetan.itjoy.space.

Клиент:
- `REPORT_API` в `site/config.js` (`https://tibetan.itjoy.space/api/report`). Вместо
  ссылки — кнопка «Сообщить об ошибке», открывающая `popover` (`site/src/ui.js`) с
  текстом предложения/слова, полем описания, кнопкой отправки; после успеха — тост с
  благодарностью и ссылкой на issue. Если `REPORT_API` пуст или запрос упал — показать
  прежнюю ссылку на предзаполненный issue (`site/src/report.js`) как запасной вариант.
- Новые строки i18n на пяти языках: заголовок, подсказка «что не так», кнопка
  «Отправить», «Спасибо, сообщение отправлено», «Не удалось отправить, откройте issue
  вручную».
- Smoke-тест не должен делать сетевых запросов к API (в тесте `REPORT_API` пустой).

### Задача 3. Грамматика внутри предложения и в момент ошибки

Есть экран `#/grammar` (`site/src/screens/grammar.js`, функция `collectNotes()`
группирует заметки `note` предложений по наборам с примерами). В игре заметка к
предложению показывается только после решения; после второй ошибки в фидбэк
подставляется текст заметки (`explain()` в `site/src/screens/play.js`), а при ошибке
на частице — подсказка про частицу.

Сделать:
- Кнопку «Грамматика» в раунде (рядом с «Подсказка»), открывающую popover с
  грамматической справкой по текущему предложению: заметка самого предложения (если
  есть), затем до трёх заметок того же набора, в чьих примерах встречаются слова
  текущего предложения (сравнивать по id слов через `contentWords()`), каждая с одним
  примером (тибетский + перевод) и ссылкой «Открыть справочник» на `#/grammar`.
  Логику подбора вынести в чистую функцию `relatedNotes(sentence, sentences, sets,
  dict, limit)` в `site/src/engine/` с тестом.
- В момент ошибки: в фидбэке появляется кнопка «Почему?», открывающая тот же popover,
  но с первой заметкой, относящейся к ошибочному слову (частица → заметки, в примерах
  которых есть это слово; иначе заметка предложения). Открытие грамматики не считается
  подсмотром: статусы слов не меняются (`revealWord` не вызывать).
- Тибетские фрагменты в заметках оборачивать `tibText()` из `site/src/ui.js`.
- i18n: `play.grammar`, `play.why`, `play.openGrammar`, `play.noGrammar` («К этому
  предложению заметок нет») на пяти языках.

### Задача 4. Перенос сайта на свой сервер: https://tibetan.itjoy.space

Факты о сервере (проверено 2026-10-13, доступ `ssh root@itjoy.space` по ключу без
пароля): Ubuntu 24.04, nginx 1.24 слушает 80/443 (apache2 установлен, но неактивен),
node v22, php, certbot, docker. Vhost-ы в `/etc/nginx/sites-enabled/*.conf`, корни в
`/var/www/<домен>`; образец конфига — `/etc/nginx/sites-enabled/quiz.itjoy.space.conf`
(80 → 301 на https, ACME-челлендж из `/var/www/html`, сертификаты Let's Encrypt в
`/etc/letsencrypt/live/<домен>/`). DNS `tibetan.itjoy.space` уже резолвится в
185.112.102.82 (похоже, wildcard), отдельную запись заводить не нужно. Пользователя
`deploy` нет.

Сделать:
1. На сервере: `/var/www/tibetan.itjoy.space` (владелец `deploy:www-data`),
   пользователь `deploy` без пароля с ключом только для деплоя, сертификат
   `certbot certonly --webroot -w /var/www/html -d tibetan.itjoy.space`, vhost по
   образцу quiz: `root /var/www/tibetan.itjoy.space; index index.html;` gzip для
   js/css/json/svg/webmanifest; заголовки кэширования: `fonts/`, `icons/` —
   `Cache-Control: public, max-age=31536000, immutable`; `sw.js`, `config.js`,
   `index.html`, `data/*.json` — `no-cache`; остальное `max-age=600`; тип
   `application/manifest+json` для `.webmanifest`; `location /api/` → задача 2.
   `nginx -t && systemctl reload nginx`.
2. Деплой из GitHub Actions: новый job `deploy-server` после `check` — `rsync -az
   --delete site/ deploy@itjoy.space:/var/www/tibetan.itjoy.space/` по ключу из
   секрета `DEPLOY_SSH_KEY` (приватный ключ пары, сгенерированной для `deploy`),
   `known_hosts` из секрета `DEPLOY_KNOWN_HOSTS` (`ssh-keyscan itjoy.space`). Секреты
   ставить через `gh secret set`. Штамп версии в `site/config.js` делать до rsync
   (как в job `deploy`).
   GitHub Pages после переезда не оставлять как второй адрес: два адреса — это два
   разных localStorage, а старый сервис-воркер продолжит отдавать кэш. Вместо
   публикации `site/` job `deploy` публикует одну страницу-редирект (папка
   `redirect/index.html` в репозитории): она ставит `<meta http-equiv="refresh">`
   и JS-переход на `https://tibetan.itjoy.space/` с сохранением `location.hash`,
   регистрирует `sw.js`, который делает `self.registration.unregister()` и чистит
   кэши `caches.keys()` → `caches.delete` (имя файла `sw.js` должно совпасть со
   старым, чтобы заменить его), и показывает текст на пяти языках: «Приложение
   переехало на tibetan.itjoy.space. Прогресс перенесите кодом: Настройки → Перенос
   на другое устройство» (строки прямо в HTML, без i18n-модулей). Поскольку старые
   пользователи ещё не видели перенос, сначала задеплоить на Pages промежуточную
   версию обычного сайта с баннером о переезде на две недели, и только потом
   редирект; дату смены записать в README.
3. Проверка: `curl -I https://tibetan.itjoy.space/` (200, HSTS не обязателен),
   `curl -I .../sw.js` (no-cache), `curl -I .../fonts/NotoSerifTibetan-Regular.woff2`
   (immutable, `font/woff2`); `node scripts/smoke.mjs` принимает переменную
   `SMOKE_URL` (добавить) и прогоняется против живого домена; в браузере на 360px —
   установка PWA, офлайн после перезагрузки, тёмная тема.
4. В README: раздел про сервер (где лежит сайт, как деплоится, как обновить
   сертификат, где лежит `report-api` и его токен), новый адрес вместо Pages везде,
   в `site/config.js` обновить `REPO_URL`/`REPORT_API`, в инструкции по Google OAuth
   origin `https://tibetan.itjoy.space` (старый `https://kotstantin108.github.io`
   убрать после смены на редирект).

Чего не делать: не трогать чужие vhost-ы и контейнеры на сервере, не класть ключи и
токены в репозиторий, не запускать сервис от root, не удалять репозиторий Pages-ветку
силой (редирект публикуется тем же workflow).
