# Задание: веб-приложение для изучения классического тибетского через игры

## Контекст

В папке проекта лежат:
- `textbooks/` — учебники, по которым строится курс (PDF/сканы/текст);
- `reference/prototype.html` — прототип игры «собери предложение из плиток». Его визуальный стиль и механику тапов (без drag-and-drop, удобно с телефона) берём за основу.

Цель: статическое приложение без бэкенда, хостинг на GitHub Pages. Пользователь учит язык, отмечая слова как знакомые; каждое следующее предложение добавляет не больше одного нового слова. Прогресс хранится локально; вход через Google необязателен и нужен только для синхронизации между устройствами.

## Языки

Интерфейс и переводы двуязычные: русский и английский, на выбор пользователя.

- Строки интерфейса лежат в `src/i18n/ru.js` и `src/i18n/en.js` с одинаковым набором ключей, хардкода в разметке нет. Тест проверяет, что ключи в двух файлах совпадают.
- Язык по умолчанию определяется по `navigator.language`: `ru*` даёт русский, всё остальное английский. Переключатель есть в настройках и в шапке. Выбор хранится в `settings.lang` и синхронизируется вместе с прогрессем.
- Переключение языка мгновенное, без перезагрузки, и меняет и интерфейс, и переводы слов и предложений.
- Все переводимые поля в данных хранятся объектом `{ "ru": "...", "en": "..." }`.
- Если перевода на выбранный язык нет, показывается перевод на втором языке с пометкой. Приложение не падает.

## Технические ограничения

- Чистый HTML/CSS/JS на ES-модулях, без фреймворков и без обязательного шага сборки. Сайт должен открываться прямо из папки `site/` через любой статический сервер.
- Шрифт: Noto Sans Tibetan (Google Fonts) с фолбэками `"Kailasa","Microsoft Himalaya","Jomolhari"`.
- Mobile-first, тап-зоны не меньше 44px, без горизонтального скролла на ширине 360px.
- Никаких внешних сервисов, кроме Google Fonts и Google Identity Services / Drive API для необязательной синхронизации.

## Этап 1. Контент из учебников (делать первым, потом остановиться)

1. Прочитай учебники в `textbooks/`. Извлеки лексику и примеры предложений.
2. Собери `site/data/words.json`:
   ```json
   {
     "nga": {
       "tib": "ང་",
       "tr": { "ru": "я", "en": "I" },
       "wylie": "nga",
       "pos": "pronoun",
       "set": "lesson-01",
       "source": "Учебник X, урок 1, с. 12"
     }
   }
   ```
   id — латиница по Wylie, без пробелов; при коллизиях добавляй суффикс (`yin`, `yin-2`).
3. Собери `site/data/sentences.json`:
   ```json
   [
     {
       "id": "s001",
       "words": ["nga", "slob-ma", "yin"],
       "tr": { "ru": "Я ученик.", "en": "I am a student." },
       "set": "lesson-01",
       "source": "Учебник X, урок 1, упр. 3",
       "note": {
         "ru": "ཡིན་ — связка, стоит в конце.",
         "en": "ཡིན་ is the copula; it comes last."
       },
       "trOrigin": { "ru": "textbook", "en": "machine" }
     }
   ]
   ```
   Предложение ссылается на слова только по id. Тибетский текст предложения получается конкатенацией `tib` слов; финальный шад `།` хранится в последнем слове предложения или отдельным служебным токеном. Выбери один способ и применяй его единообразно.
4. Наборы (`set`) соответствуют урокам учебника, порядок наборов задан в `site/data/sets.json`: id, название как `{ "ru", "en" }`, порядок.
5. **Происхождение переводов.** Перевод на язык учебника берётся из учебника. Перевод на второй язык делаешь сам и помечаешь в `trOrigin` значением `"machine"`; у слов поле `trOrigin` устроено так же. Машинные переводы в интерфейсе не помечаются, но валидатор выводит их число по языкам. Список предложений с машинным переводом попадает в `CONTENT_REVIEW.md`, чтобы их вычитал носитель или преподаватель.
6. **Не выдумывай предложения.** Бери только те, что есть в учебниках. Если хочешь предложить свои, клади их в отдельный файл `site/data/sentences.generated.json` с полем `"reviewed": false`. В приложение они не попадают, пока поле не станет `true`.
7. Напиши `scripts/validate.mjs` (запуск: `node scripts/validate.mjs`). Он проверяет:
   - каждое слово предложения существует в `words.json`;
   - у слов нет пустого `tib`, а у всех переводимых полей (`tr`, `note`, названия наборов) есть непустые `ru` и `en`; нехватка перевода — предупреждение, не ошибка;
   - число переводов с `trOrigin: "machine"` по каждому языку;
   - нет дублей id;
   - в `tib` нет латиницы и лишних пробелов;
   - для каждого набора выводит число слов и предложений;
   - выводит слова, не встречающиеся ни в одном предложении, и предложения, где больше одного слова впервые вводится в этом наборе.
8. Сомнительные места (неразборчивый скан, неясное членение на слова, спорный перевод) собери в `CONTENT_REVIEW.md` со ссылкой на страницу.

**Стоп-точка:** после этапа 1 остановись. Покажи статистику валидатора и `CONTENT_REVIEW.md` и дождись подтверждения, прежде чем делать интерфейс.

## Этап 2. Логика обучения

Модель прогресса (localStorage, ключ `tib-progress`, поле `schemaVersion: 1`):

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-12T16:00:00.000Z",
  "words": {
    "nga": { "status": "known", "updatedAt": "...", "seen": 5, "errors": 0 }
  },
  "sentences": { "s001": { "solved": 3, "lastSolved": "..." } },
  "streak": { "current": 4, "best": 9, "lastDay": "2026-10-12" },
  "settings": { "tileMode": "words", "lang": "ru" }
}
```

Статусы слова: `new` (не встречалось), `learning` (видел перевод или ошибся), `known`.

Выбор следующего предложения (`src/engine/next.js`, чистые функции без DOM):
1. Кандидаты — предложения, где ровно одно слово не `known`. Предпочтение отдаётся наборам по порядку, затем давно не решавшимся.
2. Если таких нет, берётся предложение с минимальным числом не-`known` слов.
3. Холодный старт (знакомых слов почти нет): первые предложения первого набора показываются с открытыми переводами всех слов.
4. Только что решённое предложение не повторяется подряд.

Изменение статусов:
- Слово становится `known`, если пользователь нажал «Знаю» в подсказке слова или правильно собрал предложение, где это слово было единственным новым, без подсмотра его перевода.
- `known` → `learning`, если пользователь в предложении подсмотрел перевод этого слова или ошибся позицией именно на нём.
- Ручная отметка на странице словаря ставит статус напрямую.

Проверка ответа сравнивает **тексты** плиток, а не их id: одинаковые слоги или слова в одном предложении взаимозаменяемы. В прототипе сравнение по id — это баг, не переноси его.

Стрик: день засчитывается, если решено хотя бы N предложений (N = 3, константа в конфиге). Дата берётся в локальном часовом поясе устройства. Пропуск дня обнуляет `current`.

Покрой `src/engine/` тестами на встроенном `node:test` (`node --test`): выбор предложения, холодный старт, фолбэк при отсутствии кандидатов, правила смены статусов, стрик через полночь и через пропущенный день, проверка ответа с повторяющимися плитками.

## Этап 3. Интерфейс

Экраны (хеш-роутинг, без сервера):

1. **Игра** (`#/play`) — основной экран. Плитки как в прототипе, переключатель «слова / слоги». Новое слово в предложении визуально подсвечено. Тап по слову в английском/русском переводе или по кнопке «?» у плитки показывает перевод с двумя действиями: «Знаю» и «Учу». Кнопки: «Проверить», «Подсказка», «Сначала», «Пропустить». После правильного ответа показываются предложение целиком, перевод и `note`.
2. **Словарь** (`#/dict`) — наборы списком, внутри слова со статусом, переводом, Wylie. Поиск по тибетскому, Wylie и переводу. Отметка «знаю/учу» по слову и «отметить весь набор как знакомый».
3. **Прогресс** (`#/stats`) — стрик, число known/learning, прогресс по наборам.
4. **Настройки** (`#/settings`) — экспорт прогресса в файл, импорт из файла с подтверждением, сброс прогресса, блок синхронизации Google.

## Этап 4. Необязательная синхронизация через Google Drive

- Приложение полностью работает без входа. На экране настроек и ненавязчиво (один раз, с возможностью закрыть) на экране прогресса — текст (в i18n на обоих языках, ниже русская версия): «Хотите сохранить прогресс и продолжать с другого устройства? Войдите через Google. Мы храним только файл с вашим прогрессом в скрытой папке приложения на вашем Google Диске и не видим остальные файлы».
- Google Identity Services (token client), scope только `https://www.googleapis.com/auth/drive.appdata`. Файл `progress.json` в `appDataFolder`.
- Client ID берётся из `site/config.js`. Если он не задан, блок синхронизации скрыт, приложение работает как обычно.
- Слияние при синхронизации: по каждому слову и предложению побеждает запись с более поздним `updatedAt`; стрик — `best` берётся максимальный, `current` и `lastDay` — из записи с более поздним `lastDay`. Слияние — чистая функция в `src/engine/merge.js`, с тестами.
- Синхронизация: при входе, при возврате на вкладку и с дебаунсом после изменений. Истёкший токен переполучается тихо; если не вышло — статус «Синхронизация приостановлена, войдите снова», локальная работа не прерывается.
- В `README.md` пошагово опиши настройку: проект в Google Cloud, включение Drive API, экран согласия OAuth, Client ID типа Web, authorized JavaScript origins для `localhost` и домена GitHub Pages.
